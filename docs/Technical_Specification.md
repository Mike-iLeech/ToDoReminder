# Техническое задание: приложение списка дел

## 1. Цель

Реализовать desktop-приложение списка дел с локальным хранением данных, импортом/экспортом, компактным главным окном `300×700 px`, статусами `To Do / Started / Done`, drag-and-drop с плавным визуальным перестроением, полноэкранными напоминаниями и настройками отображения.

---

## 2. Главное окно

### 2.1. Размер

- Фиксированный размер: **300×700 px**.
- Изменение размера пользователем запрещено.
- Последнее положение окна сохраняется.
- При команде «Переместить окно на основной экран» окно переносится на текущий основной монитор.

### 2.2. Список

- Все задачи идут **строго одним вертикальным списком**.
- В главном окне **никогда нет колонок**.
- При большом количестве задач список вертикально прокручивается.

> Колонки существуют **только в полноэкранном уведомлении**.

---

## 3. Модель задач

Каждая задача содержит как минимум:

- уникальный идентификатор;
- название;
- статус;
- порядковую позицию.

Статусы строго:

```text
To Do
Started
Done
```

Цикл статусов:

```text
To Do → Started → Done → To Do
```

### 3.1. Изменение позиции при смене статуса

- `To Do → Started`: задача сразу перемещается **в конец активных задач**, перед блоком `Done`.
- `Started → Done`: задача переходит в блок `Done`.
- `Done → To Do`: задача сразу перемещается **в конец активных задач**, перед блоком `Done`.

Пользователь может свободно менять порядок всех активных задач.

---

## 4. Создание и редактирование задач

### 4.1. Лимит

Максимум: **100 задач**.

При попытке создать 101-ю показать:

> Достигнуто максимальное количество задач: 100

### 4.2. Название

- Максимум **255 символов**.
- При сохранении автоматически удалять пробелы в начале и конце.
- Пустое название запрещено.

Если после trim название пустое:

> Название не может быть пустым

При редактировании:

- `Enter` — сохранить;
- `Esc` — отменить изменения и вернуть старое название.

---

# 5. Drag-and-drop

Drag-and-drop — критически важная часть интерфейса.

## 5.1. Начало перетаскивания

При начале drag:

- исходная задача остаётся на своём месте в виде **«призрака»**;
- полноценное представление перетаскиваемой задачи следует за курсором;
- призрак визуально показывает исходную позицию.

Не удалять исходную задачу из модели данных во время drag.

## 5.2. Динамическое перестроение списка

Когда перетаскиваемая задача пересекает границу соседней задачи:

- соседняя задача **сразу плавно раздвигается**;
- освободившееся место сразу заполняется ближайшим делом;
- визуально должно быть очевидно, куда будет вставлена задача.

При движении обратно:

- уже раздвинутые задачи **плавно возвращаются**;
- возврат происходит сразу после пересечения соответствующей границы.

Не использовать резкие скачки положения.

## 5.3. Место вставки

Во время drag позиция вставки пересчитывается **непрерывно**.

Она должна всегда соответствовать реальному индексу, который будет использован при отпускании.

В месте вставки одновременно показывать:

1. пустой слот размером с перетаскиваемую задачу;
2. разделительную линию.

Пользователь должен ясно видеть:

> Если отпустить сейчас — задача окажется именно здесь.

## 5.4. Выход за пределы списка

Перетаскиваемая задача не должна позволять пользователю вставить её за пределами списка.

- Нельзя удалить задачу простым вытаскиванием за пределы списка.
- Drag ограничен областью списка/окна.

## 5.5. Автопрокрутка

Если список прокручиваемый, во время drag должна работать автопрокрутка.

- У верхнего края — прокрутка вверх.
- У нижнего края — прокрутка вниз.
- Автопрокрутка работает, если в соответствующую сторону действительно есть содержимое.

Зона автопрокрутки распространяется на **края всего окна `300×700`**, а не только на область непосредственно над карточками.

### Скорость автопрокрутки

Комбинированная модель:

- зависит от расстояния курсора до края;
- чем ближе курсор к краю, тем выше скорость;
- при длительном удержании у края скорость постепенно увеличивается.

## 5.6. Пересчёт позиции во время автопрокрутки

Позиция вставки должна непрерывно пересчитываться во время автопрокрутки.

Индикатор вставки всегда должен показывать фактическое место, которое будет использовано при отпускании.

## 5.7. Завершение drag

При отпускании мыши:

- подтверждение **не требуется**;
- задача плавно перемещается в отображаемый слот;
- новый порядок **сразу сохраняется**.

Критическое требование:

> Нельзя допускать ситуации, когда визуальный индикатор показывает одно место, а после отпускания задача оказывается в другом.

# 6. Полноэкранное уведомление

Полноэкранное уведомление — отдельный режим отображения.

## 6.1. Состав

Показываются **только активные задачи**:

- `To Do`;
- `Started`.

`Done` в списке полноэкранного уведомления не отображаются.

Порядок активных задач должен быть точно таким же, как в основном списке.

## 6.2. Колонки

Колонки используются **только здесь**.

Между колонками:

- фиксированная вертикальная линия;
- толщина **3 px**;
- цвет линии совпадает с цветом текста.

Основное окно `300×700` колонок не имеет.

## 6.3. Отображаемая информация

Для каждой задачи показывать только:

- название;
- визуальный статус.

### Размер текста

- По умолчанию: **32 px**.
- Отдельная настройка.
- Диапазон: **12–100 px**.
- Шаг: **1 px**.
- Один установленный размер используется для всех задач.

### Перенос

- Перенос по словам.
- Слова нельзя произвольно разрывать.

### Выравнивание

Отдельная настройка:

```text
Слева
По центру
Справа
```

По умолчанию: **Слева**.

---

# 7. Шрифт

Выбор шрифта — отдельная настройка.

Доступны **все шрифты, установленные в системе**.

В списке шрифтов название каждого шрифта должно визуально отображаться непосредственно этим шрифтом.

Отдельная настройка начертания:

```text
Обычный
Жирный
Курсив
Жирный курсив
```

---

# 8. Цвета и прозрачность полноэкранного уведомления

## 8.1. Фон

По умолчанию:

```text
#FFFFFF
```

Белый.

Выбор:

- визуальная палитра;
- ручной ввод HEX.

## 8.2. Текст

По умолчанию:

```text
#000000
```

Чёрный.

Выбор:

- визуальная палитра;
- ручной ввод HEX.

Цвет текста используется также для разделительных линий между колонками.

## 8.3. Прозрачность

Отдельная настройка:

- диапазон `0–100%`;
- шаг `1%`.

Семантика:

```text
0%   = полностью непрозрачно
100% = полностью прозрачно
```

Прозрачность применяется **ко всему полноэкранному уведомлению целиком**:

- фон;
- текст;
- разделительные линии.

---

# 9. Предпросмотр

В настройках должна быть отдельная кнопка:

> Предпросмотр

При нажатии открывать **реальное полноэкранное уведомление поверх всех окон** на выбранном для уведомлений экране.

Предпросмотр не использует реальные задачи.

Использовать смешанный тестовый набор:

- короткие названия;
- длинные названия;
- многострочные названия;
- разные статусы.

Предпросмотр должен позволять проверить все визуальные настройки.

# 10. Напоминания

## 10.1. Опциональность

В настройках:

> Выводить выполненные дела в полноэкранном уведомлении?

Варианты:

```text
Да
Нет
```

## 10.2. Таймер

В основном окне показывать небольшой ненавязчивый таймер/индикатор.

Положение:

> левый нижний угол.

## 10.3. Запуск

После запуска приложения всегда начинается **новый полный отсчёт** от установленного интервала.

## 10.4. Изменение интервала

При изменении интервала:

- пересчитать сразу;
- текущий отсчёт сбросить;
- начать новый полный отсчёт от нового значения.

## 10.5. После скрытия

После скрытия напоминания начинается **новый полный интервал**.

## 10.6. Перезапуск текущего напоминания

Перезапуск/обновление текущего напоминания:

- не создаёт второе окно;
- обновляет существующее уведомление.

## 10.7. Пустой список

Если в момент напоминания нет задач, показывать полноэкранное сообщение:

> Вы не добавили ни одного дела в список

После этого:

- начинается новый полный интервал;
- обычный цикл таймера продолжается.

Если задачи так и не добавлены, следующее напоминание снова показывает это сообщение.

## 10.8. Скрытие

Напоминание скрывается:

- `Enter`;
- `Space`;
- `Esc`;
- любой клик мышью.

После скрытия начинается новый полный интервал.

Если конкретное действие настроено как «Открывать основное окно» — открыть основное окно.

# 15. Импорт и экспорт

Поддержать форматы:

```text
JSON
TXT
CSV
```

Поддержать режимы импорта:

```text
Заменить
Добавить
```

## 15.1. TXT

TXT содержит только названия задач, без статусов.

Порядок строк строго определяет порядок задач:

```text
строка 1 → задача 1
строка 2 → задача 2
строка 3 → задача 3
...
```

## 15.2. CSV

CSV содержит:

- название;
- статус.

Порядок строк сохраняется.

## 15.3. JSON

JSON должен сохранять структуру, необходимую для полного восстановления:

- задачи;
- порядок;
- статусы;
- необходимые метаданные.

## 15.4. Ограничение импорта

Итоговое количество задач не может превышать 100.

---

# 16. Локальное хранение

Не использовать SQL/NoSQL базу данных.

Локально сохранять как минимум:

- задачи;
- порядок;
- статусы;
- настройки;
- положение окна;
- выбранный монитор;
- настройки полноэкранного уведомления;
- шрифт;
- начертание;
- размер текста;
- выравнивание;
- цвета;
- прозрачность;
- интервал напоминаний;
- автозапуск;
- настройки поведения приложения.

После перезапуска состояние должно полностью восстанавливаться.

---

# 17. UX и анимации

Главный принцип:

> Никаких резких перестроений интерфейса там, где пользователь ожидает плавного движения.

Особенно плавными должны быть:

- раздвигание задач;
- возвращение задач;
- перемещение итоговой задачи в слот;
- автопрокрутка;
- изменение визуального положения индикатора вставки.

Приоритеты:

1. корректность порядка;
2. точность места вставки;
3. отсутствие визуальных скачков;
4. плавность.

# 18. Критический сценарий drag-and-drop

Обязательно протестировать следующий сценарий:

1. Создать минимум 10 задач.
2. Взять задачу №3.
3. Начать drag.
4. Увидеть призрак на исходном месте.
5. Перетащить задачу между №7 и №8.
6. Увидеть пустой слот и разделительную линию.
7. Увидеть плавное раздвигание соседних задач.
8. Двинуть курсор назад.
9. Увидеть плавное возвращение задач.
10. Снова двинуть вниз.
11. Проверить непрерывное изменение места вставки.
12. Подвести курсор к нижнему краю окна.
13. Проверить автопрокрутку.
14. Проверить изменение скорости автопрокрутки.
15. Проверить пересчёт места вставки во время прокрутки.
16. Отпустить мышь.
17. Увидеть плавное окончательное перемещение.
18. Проверить фактический порядок.
19. Перезапустить приложение.
20. Проверить сохранённый порядок.

Фактический порядок после отпускания **обязан совпадать с последним отображённым индикатором вставки**.

# 20. Правила для агента-разработчика

Перед изменением проекта обязательно:

1. Изучить существующую структуру проекта.
2. Определить текущий стек и архитектуру.
3. Найти существующую модель задач.
4. Найти существующее хранение данных.
5. Найти текущую реализацию статусов.
6. Найти текущий drag-and-drop, если он уже существует.
7. Найти существующую систему настроек.
8. Найти существующую систему уведомлений/таймера.
9. Найти существующую работу с системным треем.
10. Не переписывать существующие рабочие части без необходимости.

Изменения должны быть минимально инвазивными и совместимыми с текущей архитектурой.

### Особое требование

Не считать drag-and-drop завершённым только потому, что порядок технически меняется.

Он считается реализованным только при одновременном наличии:

- призрака исходной задачи;

# 23. Правильный порядок разработки

**Не пытаться реализовать всё приложение сразу.**

Qwen 3.6 35B A3B должен выполнять разработку строго по этапам. После каждого этапа необходимо запускать приложение и проверять его работу до перехода к следующему этапу.

Главное правило:

> Сначала сделать простое работающее ядро приложения, затем интерфейс, затем управление порядком, затем drag-and-drop, затем настройки, затем напоминания, затем импорт/экспорт, затем упаковку и финальное тестирование.

Не переходить к следующему этапу, если предыдущий содержит критические ошибки.

## Этап 0. Анализ окружения и создание проекта

Перед написанием основной логики:

1. Проверить ОС и Python.
2. Проверить наличие Python 3.12+.
3. Создать виртуальное окружение.
4. Установить PySide6.
5. Создать минимальную структуру проекта.
6. Создать `requirements.txt`.
7. Запустить минимальное Qt-окно.

На этом этапе не реализовывать задачи, настройки, drag-and-drop или уведомления.

Критерий завершения:
- приложение запускается;
- окно Qt появляется;
- ошибок в консоли нет.

## Этап 5. Базовый drag-and-drop

Только после того как обычный список и порядок полностью стабильны, начинать drag-and-drop.

Пока не добавлять сложные анимации.

Критерий завершения:

## Этап 6. Полноценный визуальный drag-and-drop

После базового drag реализовать все утверждённые визуальные требования.

Последовательность внутри этапа:

### 6.1. Ghost

- исходная задача остаётся призраком;
- оригинальная модель данных не меняется до завершения drag.

### 6.2. Перетаскиваемое представление

- отдельная карточка/визуальное представление следует за курсором.

### 6.3. Placeholder

- пустой слот размером с задачу;
- разделительная линия.

### 6.4. Динамическое раздвигание

- пересечение границы соседней задачи сразу меняет предполагаемый индекс;
- соседние элементы плавно раздвигаются;
- при движении назад плавно возвращаются.

### 6.5. Непрерывный расчёт индекса

На каждом обновлении позиции курсора вычислять:

```text
drag_position → target_index
```

Именно `target_index` должен использоваться при окончательном сохранении.

### 6.6. Финальная анимация

При отпускании:

```text
placeholder → плавное перемещение задачи → новый порядок → save()
```

Критерий завершения:
- визуальная позиция всегда совпадает с фактическим результатом.

# 24. Правила работы Qwen 3.6 35B A3B

Этот раздел является инструкцией агенту-разработчику.

## 24.1. Не делать всё за один проход

Не пытаться сразу написать весь проект.

После каждого этапа:

3. исправить ошибки;
4. только после успешной проверки перейти дальше.

## 24.2. Сначала рабочий код, потом красота

Приоритет:

```text

4. корректный drag-and-drop
5. корректные напоминания
6. настройки
7. визуальная полировка
```

Не тратить время на декоративные эффекты, пока основная логика не работает.

## 24.3. Не усложнять стек

Запрещено без необходимости добавлять:

- React;
- Vue;
- Electron;
- Node.js;
- TypeScript;
- SQLite;
- ORM;
- REST API;
- web server;
- Docker;
- отдельный backend;
- сторонние UI-фреймворки;
- сторонние state-management библиотеки.

Всё приложение должно работать локально как обычное Windows desktop-приложение.

## 24.4. Предпочитать стандартный Qt API

Если Qt уже умеет нужную функцию, использовать Qt.

Например:

- окно → `QWidget` / `QMainWindow`;
- таймер → `QTimer`;
- трей → `QSystemTrayIcon`;
- монитор → `QScreen`;
- системные шрифты → `QFontDatabase`;
- drag → Qt mouse/pointer events;
- анимации → `QPropertyAnimation` / Qt Animation Framework;
- цвет → `QColorDialog`;
- файлы → `QFileDialog`.

Не искать стороннюю библиотеку для задачи, которую уже решает Qt.

## 24.5. Не ломать рабочее

Перед изменением существующего кода:

1. прочитать файл;
2. понять его назначение;
3. найти вызывающие его места;
4. изменить минимально необходимую часть;
5. запустить тест.

Не делать массовый rewrite проекта без необходимости.

## 24.6. Проверять drag особенно тщательно

Drag-and-drop является самой сложной частью проекта.

Если после реализации drag:

- визуальный placeholder показывает одно место;
- а фактическая вставка происходит в другое;

то этап считается **не выполненным**.

Сначала исправить расчёт индекса, и только затем продолжать.

## 24.7. Не создавать лишние абстракции

Для проекта такого размера предпочтительнее простой код, который можно прочитать целиком.

Не создавать:

```text
AbstractTaskRepositoryFactory
TaskStateOrchestrator
DragStrategyProvider
NotificationServiceFactory
```

если для этого нет реальной причины.

Простые классы и функции предпочтительнее сложных паттернов.

## 24.8. Комментарии

Комментарии писать только там, где объясняется неочевидное поведение.

Особенно документировать:

- расчёт индекса drag;
- placeholder;
- автопрокрутку;
- сохранение порядка;
- работу с несколькими мониторами;
- восстановление положения окна.
